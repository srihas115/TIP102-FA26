# Contributing

This repo holds my personal problem sets and notes for CodePath's **TIP102** course, so it is not a typical open-source project looking for contributors. That said, if we worked through a problem together in session and you have a fixed or improved solution, I would love to see it!

## Ways to Contribute

- Open an issue if you spot a bug, a wrong problem statement, or an outdated note.
- Open a pull request if you have an alternative or improved solution to a problem.
- Reach out directly through Slack, LinkedIn, or email if it is easier to show me your version.
- If we are using VS Code Live Share in a breakout room, live edits are welcome too.

## What I Am Looking For

A working solution alone is not enough. Please also:

- Explain why it works.
- Keep the original function or method signatures unless the prompt itself is wrong.
- Add useful comments for the approach, edge cases, or tricky invariants.
- Include or preserve simple test calls when a problem file already has them.

## Fixing Problem Files

The `.md` and starter `.py` files come from CodePath materials and may occasionally include typos, broken examples, or syntax issues. If you find one, fix it directly and mention it in the PR.

## Better Approaches

If you find a cleaner or more efficient approach, prefer adding it alongside the existing solution with a short explanation of the tradeoff instead of deleting the older version outright.

## Style

- Solutions are written in Python.
- Prefer clear, idiomatic code over clever one-liners.
- Comment for the "why," not the obvious "what."
- Keep problem files focused on the prompt and solution.

## Code of Conduct

Be kind, be constructive, and keep feedback focused on the code.
